## 隔离与命令约定

每案及每个故障子窗口使用独立临时 HOME、合成 R/C/V、Git 主 checkout 项目 P、隔离执行器信号与已核验源 S；不使用真实 `~/.agents-group`、`~/.mem-sharing`、执行器目录或真实凭据。证据写在被测 HOME 之外的独立 raw 目录。预先记录绝对路径、平台、Python/Git 版本、源码 commit/清单、环境隔离范围与未隔离面。仅改 HOME 不证明全部执行器发现已隔离。

下列 I/A/REC 是命令展开记号，不是新增 CLI、shell 函数或可直接粘贴的整段脚本：

- `I`：`python3 -B "$S/scripts/install.py" --source "$S" --commit "$COMMIT" --version "$VERSION"`；manifest 分支改用 `--source-manifest "$SOURCE_JSON"`，不混用。恢复/获取命令不带 I 的普通安装参数，help 可只调用脚本 `--help`。
- `A`：`python3 -B "$C/scripts/agm.py"`；未安装/冷启动用已核验 S 下的 agm.py，证据注明来源。
- `REC`：`python3 -B <已核验完整安装器或固定恢复入口> --recover "$MANIFEST" --action continue|rollback`；MANIFEST 为实际 journal 绝对路径；安装器与固定 recover.py 的实际接口分别记录，选择具体 action，不原样传竖线。
- `AP/RP/PP`：机器安装、独立恢复、项目计划的绝对路径批准文件，分别绑定本次真实确认，不凭空填确认来源。
- 分号和“获批后”表示独立采集步骤；每个实际 argv 单独留存，预览并不授权后续操作。

每案必须采集的原始证据（下表 E0）：实际 argv、cwd 与隔离环境、起止 UTC、退出码、原始 stdout/stderr；前后路径树（包括隐藏项、节点类型、权限、链接文本）、文件长度/SHA-256/mtime；逐文件字节 diff、批准与计划、op/manifest/恢复位置。外部合成哨兵也留前后指纹。失败保存现场，不修饰成成功；每个子场景/窗口单独编号。目录清单与证据索引仅供核对，不能生成自动 passed 判定。不得保存真实隐私原文。

## 命名与后续裁定

隔离 HOME 内定义旧源 O＝`~/.agents-group`，新 R＝`~/.mem-sharing`，C＝`~/.local/share/mem-sharing`，V＝`R/var/registry.json`，版本库存＝`~/.local/share/mem-sharing-versions`，bootstrap＝`~/.mem-sharing-install-<op>/`。product_id 为 `mem-sharing`，受管标记前缀为 `mem-sharing:*`，源码 URL 为 `https://github.com/vincent4j/mem-sharing`。项目 P 与升级前驱版本 P 的旧记号在执行证据中须分别标为项目根和前驱源，避免混淆。

v0 的源与目标必须分离：O 原地不动，只复制 memories/references；不复制或激活 skills、mcp、旧脚本与状态。取消旧 skills 迁移及产品 Skill 投影的正向验收，仅检查其未被创建或接管。旧同路径夹具只保留恢复语义，不能代表新真机路径。

默认启用只建立项目规则与协议，不初始化项目经历库。CLAUDE 引用及 WorkBuddy 桥接按项目实际使用产生。CK 用户级安装与项目首次 `/context-keeper` 激活分别采证。全部案例为**未执行**，新增流程的调用点未冻结时保留 TODO，不凭文档猜 CLI。
