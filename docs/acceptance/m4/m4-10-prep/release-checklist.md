# 发布与运行验收清单

本文件是后续执行规格，不是发布、迁移或恢复暂停任务的授权。当前结果见[验收总览](../../index.md)，Paseo发行操作见[发行工具](../../../../tools/plugin-release/README.md)。

## 固定来源与变更验证

1. 获批版本、完整clean提交、schema/structure、受管文件字节与模式一致；文档变化也会改变产品树。使用精确conversion，不复用旧版本报告里的draft、旧批准或synthetic提交。
2. 按实际diff运行必要回归，记录真实命令/退出码/数量。旧冻结通过只能证明对应版本，定向与全量不能叠加。
3. 安装材料仅含受管集合；检查产物内本地链接闭合，项目CK、私文、凭据、临时证据不进入payload。Paseo还需common/notice一致、S/R校验和固定渠道来源。
4. 已装同版异内容、未知前身、漂移或缺精确conversion均停止；不删账、不改marker、不放宽preserve。中断恢复使用原journal固定工具；V已提交后的continue收尾不等于允许rollback，主动降级需另有精确转换与批准。
5. 用户授权对应提交/推送/tag/公开发布分别判断。源码提交不等于公开发行，CI通过也不等于原生验收。

## 环境、保全与批准

- 记录实际进程用户、HOME/daemon配置根、endpoint、工具版本和Git主checkout。临时HOME、同机原生宿主、独立用户/VM是不同隔离层，不能互相冒称。
- 真实现场操作前明确最小对象、所有权、before字节/模式/链接、恢复材料和顺序；备份必须可验证。保全私文/上游CK/凭据与无关项目，不自动清未知锁或旧源。只恢复本操作对象，第三态拒绝。
- 逐层记录：依赖检查→来源确认→只读预览→精确批准→执行→文件/台账读回→新会话。无批准不执行计划内写入，下载资产、export、机器安装、CK源获取/安装分别确认。
- 登录、验证码/二次验证由用户处理，不复制日常凭据。页面由章教授执行inspect→action→verify；窗口/目标/提交状态不明即停止，不重发未知请求。
- 临时目录/操作ID每次唯一。历史固定路径仅供定位，不是可直接重放的脚本。

## 合成项目与新会话

每项在获准的独立项目验证：fresh无AGENTS/专属目录/CK库；legacy分别保留合成AGENTS、Claude正文、WorkBuddy原生正文。不要预建客户端专属对象来冒充实际客户端创建行为。保存前后集合、类型、模式、hash和Git身份，答案不放进prompt/manifest或会自动注入的历史。

| 验证层 | 通过要求 |
| --- | --- |
| 用户公共规则 | 用户入口→索引→主题的实际读取依据及独立随机约定应用 |
| 项目规则 | 实际加载依据、项目约定应用与原文保全；原生注入/工具读取/自述分开 |
| 默认入口 | 使用前缺失，实际执行器使用后按合同产生，重复不增生 |
| CK | 独立安装、Skill实际发现、新会话读取、首次命令/保存分别留证；configured不是激活 |
| 禁止与停用 | 禁止保存零新增、迁移门禁停止、disabled不自动恢复；解除要显式批准 |
| 取消与恢复 | 拒绝不执行业务变更，运行取消保留journal，源/插件移除后仍能按原材料恢复 |

公共临时规则在当前测试结束或阻断后按before恢复并撤主题；不能因等待下一轮无限保留，也不能复用失效标记。无法隔离历史自动注入时说明来源局限。

完整接力须分别留新会话与库diff：Codex经CK保存随机事实/待办→Claude普通续接并更新→WorkBuddy读取累积并追加→Codex新会话核对来源。缺一环、答案提示或其他版本的成功不替代四会话闭环。
