## 建议执行顺序

1. **自动回归与冻结**：01；准备开发依赖，跑当前完整Python/Node/类型检查，补固定pin fixture。确认拟发布范围和版本，修正文档03，再固定新S并生成R，关闭02。任何产品修复后重新建立对应来源与证据。
2. **独立安装与功能**：04—11，用合成项目和随机测试事实；先验六家读取、菜单和CK，再验四会话接力。
3. **Paseo整链路**：12—15；使用同一R，从新机器依赖开始，不直接跳到已装Host状态读回。
4. **卸载与恢复**：16—19最后做；先完成备份和外置恢复探测，逐对象展示批准，再执行实际清理。验证码/账号验证由用户处理，不复制生产凭据。
5. **发布判定**：20；记录每组pass/fail/blocked/not_in_scope和证据，已知失败阻断；未验平台不写成支持。两种安装入口都对外提供时，两边均须取得实际安装证据。

本轮盘点不执行真实安装、卸载、修改用户规则、生成正式payload、tag或公开发布，也不自动恢复此前叫停的桌面会话。后续逐项执行时按当前请求和精确计划确认操作对象。
