# 记忆共享与融合 PRD

- **状态：** 用户需求已确认；实现与运行验收未验证。本轮仅保存需求，不代表现有实现已满足本 PRD。
- **需求来源：** 2026-11-03 用户审定需求，由主 Agent 在任务交接中完整转述。
- **范围：** 用户记忆与当前项目的项目记忆融合；项目经历由可选 Context Keeper 管理，不参与融合。
- **评审：** 主 Agent 负责未决项评审。当前需求无已知阻塞产品问题；冲突采用哪份原文、已有公共项转存何处，均在实际使用时逐条询问，不要求用户现在重复确认。

## 1. 目标与术语

让用户先看清各 Agent 已有记忆的共同部分与差异，再选择哪些内容共享。推荐、选择、最终确认与实际修改分开；保留完整原文、准确来源和恢复能力。

面向用户只使用三类名称：

| 名称 | 含义与范围 |
| --- | --- |
| 用户记忆 | 本次实际接入且核验安装的受支持 Agent 使用的用户级记忆。 |
| 项目记忆 | 仅当前项目内的记忆，以根 `AGENTS.md` 为已有公共基座。 |
| 项目经历 | 由可选 Context Keeper 独立保存、查找和续接的经验内容，不参与本次融合。 |

用户最新确认类别为“用户记忆／项目记忆／项目经历”。操作动词统一使用“共享”；类别名称不另起别称。`AGENTS.md`、`CLAUDE.md` 等文件名及读取入口等技术描述可保留。本 PRD 确认术语要求，不表示本轮已修改现有界面或其他文档。

## 2. 用户记忆：参与范围与两块推荐

### 2.1 参与集合

支持的六家为 Codex、Claude Code、WorkBuddy、OpenCode、DeepSeek Harness、ZCode。每次分析仅以其中**本次实际接入且核验安装者**为参与集合，数量记为 N；未参与者不计入分母，不把六家固定作为全覆盖门槛。

读取结果必须区分：

- 文件缺失或内容为空：该来源无内容。
- 读取失败、权限不足、截断或其他不完整读取：该来源未知，不能当作无内容，也不能据此推定全覆盖。
- 完整读取：才能比较内容及来源。

### 2.2 推荐分组

| 条件 | 展示与默认行为 |
| --- | --- |
| N ≥ 2，且所有参与者都有同内容 | 放入“默认共享”块，作为默认方案；执行仍需最终清单确认。 |
| 至少两家有同内容，但未覆盖全部参与者 | 放入“由你选择是否共享”块，默认不选。存在未知来源时不能提升为全覆盖。 |
| 只有一家有内容 | 默认留在原处；用户可明确指定共享，不能仅因它是唯一参与者而默认共享。 |
| N = 1，即使覆盖该参与者 | 不满足“默认共享”条件，按单家内容处理。 |
| 受保护协议、产品生成说明或显式 Agent 专属内容 | 不因重复而迁入公共记忆，原处保全。 |

“默认共享”是推荐，不是立即修改。单家内容可在用户要求时查看并指定共享，不强行当作多家共同内容。

## 3. 同内容判定与选择交互

### 3.1 判定边界

只有正文除格式差异外相同，且语境与作用域相同，才能自动推荐为同内容。仅语义类似、相互冲突、归属不清或语境/作用域不同的内容，只能列为待用户确认，不自动融合或改写。保留每份完整原文，不能用摘要替换正文。

受保护内容即使文字相同也不参加公共迁移。同一句话出现在不同作用域，不能仅凭文字重复视为共同要求。

### 3.2 展示与编号

- 两块分别为“默认共享”和“由你选择是否共享”，各条以一句摘要、完整来源定位及“查看完整原文”入口展示。
- 两块使用全局连续、稳定的编号，不各自从 1 开始；在同一份有效计划内，查看、选择和最终清单沿用原编号，不因选择或展开原文重新编号。
- 用户只输入待选序号，例如 `3、4`，即可选择对应待选项；也支持 `共享 3、4`。
- 默认块中排除某条，必须明确输入 `不共享 2` 之类指令；只输入待选编号不会排除默认项。
- 支持组合输入，如 `共享 3、4，不共享 2`。
- `按默认方案` 表示仅保留默认项，不增加待选项。
- `查看 3` 只读展示相关完整原文与来源，不选择、不执行、不修改文件。
- 无效或含糊的编号指令需澄清，不能猜测用户想执行哪项。

### 3.3 最终确认

分析与选择阶段明确告知“尚未修改”。用户选完后，先展示**完整修改清单**，至少列出：参与范围、保留的稳定编号、完整迁移内容与来源、公共目标、原生来源精确删除片段、保留内容、必要读取入口、异常恢复安排，以及已有公共项被排除时确认的保留位置。摘要不能代替可查看的完整迁移正文。

用户确认这份最终清单后才执行。选择编号、查看原文或接受默认推荐均不能替代最终修改确认。

## 4. 迁移、保全与恢复

1. 共享内容按完整原文迁入公共目标，不擅自摘要、压缩、合并改写或丢弃语义类似/冲突项。
2. 核实公共内容完整、各家必要读取入口正确之后，才删除原生文件中对应的准确来源片段。
3. 不先删来源，不按关键词粗删；原生文件中的独有内容、未选内容、受保护协议、产品生成说明及 Context Keeper 协议均保全。
4. 公共和原生文件操作必须有失败恢复能力；任一步失败不得宣称迁移完成，必须保留可恢复的完整内容与操作状态，避免只删未存或丢失来源。
5. 执行前若来源文件或相关目标/入口发生漂移，旧计划及其批准失效。重新读取、生成修改清单并再次确认，不沿用旧批准执行；新计划明确替代旧计划，不静默把旧编号套在新内容上。
6. 恢复能力及入口核验须通过实际验证，配置存在或静态检查不等于迁移成功。本 PRD 不预定事务、备份或恢复的技术实现。

## 5. 项目记忆：当前项目与文件去重

- 仅分析当前项目。其他项目、用户记忆与项目经历不因本次项目融合而变化。
- 以独立来源文件去重；同一根 `AGENTS.md` 被四家读取仍只算一个来源，不能计成四票。文件关系必须按实际来源核验，不能按显示的 Agent 名重复计数。
- 现有根 `AGENTS.md` 是公共基座，原有内容保留。独立的 `CLAUDE.md`、`.workbuddy/memory/MEMORY.md` 等文件按同内容、覆盖与用户选择要求展示两块；单文件独有内容默认原处保留。
- 项目层面的共同内容覆盖按去重后的独立参与文件判定；仍需至少两个独立来源才能自动推荐共同内容。已有 `AGENTS.md` 条目归默认保留，可对其他来源中已确认同文的对应内容去重，不能进入“由你选择是否共享”待选组；其已有共享状态不因重新推荐而取消。
- 用户选择共享的内容迁到根 `AGENTS.md`；对其他文件仅删除已完整迁移且入口核验后的对应片段，并保留必要读取入口、独有内容、未选内容及受保护内容。
- 用户排除已有 `AGENTS.md` 公共条目时，必须先逐条询问要保留在哪里，并将答案写入最终清单；不能默认删除、默认转移或自行决定归属。用户未回答前不执行该条移除。
- 项目经历由可选 Context Keeper 管理，不参与融合；不得修改上游 Context Keeper 源码或以融合名义迁移其协议与经验记录。

## 6. 完整用户提示语示例

以下均为**交互示例，不是本机检测证据**。每项可查看完整原文和来源；详细判定与迁移边界见前述章节。

### 6.1 用户记忆示例：三家参与

> 已找到并核验安装 Codex、Claude Code、WorkBuddy 这 3 家，**目前尚未修改任何文件**。
>
> **默认共享**
>
> 下面两项三家都有，建议默认共享：
>
> 1. Git 提交使用中文。
> 2. 修改代码前先理解现有实现。
>
> **由你选择是否共享**
>
> 下面几项只在部分 Agent 中找到，请选择是否共享：
>
> 3. 修改后运行相关测试。（Codex、Claude Code）
> 4. 表达简洁，先给结论。（Claude Code、WorkBuddy）
> 5. 新增依赖前先确认。（Codex、WorkBuddy）
>
> 请告诉我你的选择：
>
> - `3、4`：保留默认项，并共享 3、4。
> - `不共享 2`：排除默认项 2。
> - `共享 3、4，不共享 2`：共享 1、3、4。
> - `按默认方案`：只共享 1、2。
> - `查看 3`：只查看完整原文和来源，不修改。
>
> 选定后，我会展示最终修改清单，请你确认后再执行：将选中内容完整保存到公共记忆，再删除原文件中对应的重复内容；独有和未选内容保留。

### 6.2 项目记忆示例：三个独立文件

本例 Codex 读取根 `AGENTS.md`，Claude Code 使用独立 `CLAUDE.md`，WorkBuddy 使用独立 `.workbuddy/memory/MEMORY.md`。默认项 1、2 在三份文件都有；待选项 3、4、5 仅在后两份文件中出现。按独立文件计算来源，不按读取同一文件的 Agent 数计票。

> 当前项目已找到 `AGENTS.md`、`CLAUDE.md`、`.workbuddy/memory/MEMORY.md` 这 3 份文件，**目前尚未修改任何文件**。
>
> **默认共享**
>
> 下面两项三份文件都有，保留在公共 `AGENTS.md`，整理其他文件中的重复内容：
>
> 1. Python 仅使用标准库，不增加第三方依赖。
> 2. 修改时同步更新相关文档。
>
> **由你选择是否共享**
>
> 下面几项只在部分文件中找到，请选择是否共享：
>
> 3. 修复问题时补充回归验证。（Claude Code、WorkBuddy）
> 4. 新增实现时优先复用已有能力。（Claude Code、WorkBuddy）
> 5. 提交前说明改动与验证结果。（Claude Code、WorkBuddy）
>
> 请告诉我你的选择：
>
> - `3、4`：保留默认项，并共享 3、4。
> - `不共享 2`：排除默认项 2。
> - `共享 3、4，不共享 2`：共享 1、3、4。
> - `按默认方案`：只共享 1、2。
> - `查看 3`：只查看完整原文和来源，不修改。

>
> 选定后，我会展示最终修改清单，请你确认后再执行：将选中内容完整保存到公共 `AGENTS.md`，再删除其他文件中对应的重复内容；独有和未选内容保留。本次只整理当前项目，其他项目、用户记忆和项目经历不动。

## 7. 验收场景与证据要求

以下为后续实现的验收要求，当前全部**待实现核验/待运行验收**。本轮文档结构检查不代表这些场景通过。

| 场景 | 预期结果 |
| --- | --- |
| N = 3，三家均有相同正文且语境/作用域相同 | 默认共享；展示来源和完整原文入口，最终确认前零修改。 |
| N = 3，仅两家有同内容 | 待选，默认不增加；只输入待选序号即可选中。 |
| N = 1，唯一参与者有内容 | 不默认共享；用户明确指定后才能进入最终清单。 |
| N ≥ 2，仅一家有内容 | 默认留原处，允许用户明确指定共享。 |
| 未参与的受支持 Agent 未安装或未接入 | 不计入 N，不以六家固定作为覆盖分母。 |
| 文件缺失、空、读取失败、截断 | 缺失/空记无，失败/截断记未知；未知不被推作全覆盖。 |
| 格式不同但正文及语境/作用域相同 | 可推荐；迁移仍保留完整原文，不自行改写。 |
| 语义类似、冲突、归属不明或作用域不同 | 待用户逐条确认；不自动融合，不丢任一完整原文。 |
| 受保护协议、产品生成说明、显式专属内容重复 | 保留原处，不因出现次数多而共享迁移。 |
| 两块编号与查看 | 全局连续、同一有效计划内稳定；查看 n 零修改、不改变选择。 |
| `3、4` / `不共享 2` / 组合输入 / 默认方案 | 分别按示例解释；默认方案不增加待选，默认块排除须明确。 |
| 选择完成但尚未确认最终清单 | 不执行修改；清单可查看完整原文、来源精确片段、目标与保留位置。 |
| 原生片段删除 | 公共正文完整及各家入口核验成功后才删准确片段，不关键词粗删。 |
| 独有、未选内容及 CK 协议 | 迁移与恢复前后完整保留。 |
| 来源、公共目标或入口在批准后漂移 | 旧批准失效，重新分析并确认新清单，不套用旧编号批准。 |
| 公共写入失败、入口核验失败、原生删除部分失败 | 不报告完成，完整内容与恢复状态可用；验证恢复后无内容丢失。 |
| 同一 `AGENTS.md` 被四家读取 | 一个独立来源，不算四票；不据此制造默认共享。 |
| 独立项目文件的共同内容 | 两块展示，选中内容完整迁到 `AGENTS.md`，其他文件只删对应片段并保留必要入口。 |
| 已有 `AGENTS.md` 条目的分组与排除 | 归默认保留，不进入待选组；可对其他已确认同文来源去重，排除时先问保留去向。 |
| 明确排除已有 `AGENTS.md` 公共条目 | 先询问保留位置，未答不删；回答纳入最终清单后再确认执行。 |
| 项目隔离 | 其他项目、用户记忆、项目经历不变；不修改上游 Context Keeper。 |

验证需分别保留推荐结果、只读选择行为、最终批准、实际文件变化及失败恢复证据。静态检查、配置声明与示例文本不代替真实读写/恢复或宿主运行证据。

## 8. 实现设计边界与本轮交付

语义识别策略、格式差异的技术判定、实现模块划分、迁移与恢复机制留待实现设计；不在需求保存阶段指定算法、虚构新版本、扩展新增产品能力或声明实现完成。冲突原文的取舍及已有公共条目的保留位置，按实际内容逐条询问，不是本轮重复确认项。

本轮交付仅为本独立 PRD 及已有 Context Keeper 记录库中的最小成果索引。不创建 `docs/prd/` 体系、不启用 hook、不修改项目入口、不编码、不提交或推送。产品实现、运行验收与主 Agent 最终评审结论分别以其后续证据为准。
