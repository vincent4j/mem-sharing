# 安装与原生入口 PRD

## 目标与范围

用户直接使用 GitHub README 的普通安装请求，不依赖维护者给特殊命令。安装器解析可信固定来源，展示实际范围；不以临时源码路径作为长期 Skill 入口。

默认给六家范围内本机确实已安装的 Agent 接入；用户可明确只选部分。CLI、App、目录残留和登录状态是不同事实，不能把空目录当已安装，也不能把无账号当作无法安装文件。

## 安装交互顺序

1. **环境检查。** 检查 Python >=3.9、Git 和六家实际安装事实，汇总：“环境检查完成。将为以下 Agent 安装 memSharing：〈实际名单〉。安装后，它们可以使用同一份公共用户记忆。按回车开始安装。”真实回车批准本次精确计划，不引用 Skill 或内部批准机制解释等待，不要求其他确认语；EOF、非交互空输入不批准。内部计划、备份和锁内复核保留，不向用户解释台账、指纹或内部修改清单。
2. **静默安装。** 完成仅报告：“memSharing 已安装。公共用户记忆：~/.mem-sharing/memories。已接入：〈实际名单〉”。未完成融合不报融合成功。
3. **展示融合方案。** Agent 完整阅读语境后，展示“建议合并的相同规则”和“需要你确认是否合并”；空栏目不展示；所有非空 optional/single 待选必须逐项显示，不因不推荐而隐藏。每条列来源 Agent 和原生文件，一个规则只一个稳定编号；不同标题须经本次精确等价提案判断，不靠同文字自动合并。
4. **选择即执行。** “按默认方案”“不合并2”“再加入7”等按实际编号选择，直接执行并简报；查看零写、专属和未选保留。只有现场实质变化才停下，不二次确认。外层收到用户回车/选择后直接绑定内部计划执行，不再进入 TTY 重问。
5. **最后问 CK。** 公共整理完成或明确暂不整理后，才问：“为了让 Agent 在新会话中接着上次的项目进展、决策和经验继续工作，需要再安装 Context Keeper。是否为本机已安装的〈逐名列出的实际安装名单〉安装？回复‘安装’或‘跳过’。”只有“安装”批准；回车、EOF、跳过不准备 CK 安装计划。固定上游不支持者准确报告，安装完成再提醒 `/context-keeper`。

## Context Keeper 尾步文案与范围

> 为了让 Agent 在新会话中接着上次的项目进展、决策和经验继续工作，需要再安装 Context Keeper。
>
> 是否为本机已安装的〈实际检测到的 Agent 名单〉安装？回复“安装”或“跳过”。

名单从六家中本机实际安装者生成，不固定三家，也不限制为本次选择接入 memSharing 者。不写“同作者”。不因同意 memSharing 安装就默认同意这个独立产品；无响应和非交互 EOF 不是同意。非交互接口在尚未选择时返回待选择状态、完整问句和实际名单，交由外层 Agent 展示；不得把未选择记成已跳过，也不准备 CK 安装计划。

用户同意且实际安装成功后，提醒在需要的项目使用 `/context-keeper`，首次使用按其流程创建记录库。跳过不影响公共用户记忆；失败独立报告，不回滚已成功的 memSharing，也不合报成功。

固定上游 `86af15073c1da7fedddc34342eb10bba64062b73` 已支持六家；本项目只更新集成，不修改上游源码。目标名单与固定上游版本的实际能力必须分别核实：不能给不支持的旧版本传未支持参数并宣称成功，也不能为了兼容旧三家继续把产品目标名单固定为三家。

固定版安装器的 Agent 输出顺序与探测顺序独立核对；多个 Agent 共用的 Skill 目录只列一次。用户级规则只保留上游短入口，细则按需读取 Skill；文件配置完成与新会话运行验收分别报告。

## 原生 Skill 与增量安装

每个被选 Agent 安装用户记忆入口及原生 `skills/mem-sharing/SKILL.md` 薄入口，指向持久核心。description 为“多 Agent 记忆共享与融合，给你的每一个 AI Agent 同一份记忆。”。

| Agent | 默认原生 Skill 路径（相对用户 HOME） |
|---|---|
| Codex | `.codex/skills/mem-sharing/SKILL.md` |
| Claude Code | `.claude/skills/mem-sharing/SKILL.md` |
| WorkBuddy | `.workbuddy/skills/mem-sharing/SKILL.md` |
| DeepSeek Harness | `.dsh/skills/mem-sharing/SKILL.md` |
| ZCode | `.zcode/skills/mem-sharing/SKILL.md` |
| OpenCode | `.config/opencode/skills/mem-sharing/SKILL.md` |

同名非受管文件、符号链接、受管内容漂移不得覆盖。自定义根依据支持合同处理，未支持的重定向拒绝；技术保护在执行器与按需 Skill 中，不塞入常驻用户规则。

周一只装 Codex，周二装了 Claude，周三补装 memSharing 给 Claude：复用同一公共中枢，新增 Claude 入口和 Skill；读取其已有私文提出增量融合，不能重新复制已有公共规则或重复创建中枢。公共内容仅在用户选定增量方案后变化。

同版本同范围重复安装返回“已安装，已接入。”；无变更、无额外融合、无额外批准，文件字节与元数据不变。无参入口须能验证已有可信来源；缺失与损坏来源区别处理，不能伪造发行凭据。

## 验收标准

覆盖六家全装、选择子集、后装新 Agent、重复零写、未知同名与链接拒绝、失败恢复、无参入口。安装对话验证顺序与实际输出，不能只查模板字符串。名单与结果一致；文件层成功不冒称客户端实际读取成功。

固定干净源码默认从受跟踪的核心版本元数据读取版本，无须用户补内部版本。显式版本与源码元数据冲突时拒绝；历史缺元数据源保留显式版本合同，发行来源以自身 manifest 为准，不借用插件版本。
