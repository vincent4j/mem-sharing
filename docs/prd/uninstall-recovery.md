# 全机卸载、归还与恢复 PRD

## 全机范围

用户卸载 memSharing 时，移除全部已安装 Agent 的产品 Skill 和受管引用，不因在哪家发起就只卸载哪家。自然语言卸载可进入正式路由，不要求先输入斜杠命令或知道源码位置。

先展示实际范围并取得覆盖本次操作的授权。融合选择即执行的规则不等于任意卸载自动获准。既有精确授权不重复索取；未知资产、漂移和未完成事务停止处置并说明。

## 正文归还

把公共用户记忆的实际完整内容直接写回各家原生用户记忆。产品插入的 Claude 布局分隔符，仅在绑定的正式安装 producer、完整 before/after 与当前拆除结果能够精确重放时退休；原有首尾空白、预存引用的原空白不 trim。不得只放指向归还副本的引用，不留下 `user-rules.md` 导航条目或空的产品目录标题。

仅移除可证明由产品生成的导航、操作合同和引用。保留用户自写的同名标题、链接、代码围栏、私文和 Context Keeper 内容，不能凭关键词删除。多次融合按来源依赖正确归还，保留重复来源次数、后续公共新增/修改及合法原生编辑。

融合生成的合法公共读取入口（包括旧 `memory-index` 块）属于卸载归还闭环。依据真实生产事务与完整指纹证明，在同一卸载计划中归还正文、移除入口；不得把正常卸载拆成先独立归还、再重新卸载的额外确认。缺少证明或发生漂移时仍拒绝，不能因带产品标记就认领任意正文。

机器资产与宿主插件分别报告。仍有产品宿主义务时整体不能冒称完整卸载；不能触动无关插件、daemon 或账号。卸载本产品不等于卸载 Context Keeper。

## 安全与恢复

建立外置完整备份及可核对清单，产品核心删除后仍可独立恢复。锁内复核当前状态与批准计划；先归还核验，再移除引用/Skill与已知产品资产。保留失败状态及恢复路径，不盲删未知目录，不伪造缺失的历史 manifest。

陈旧锁须核实进程与现场，不能默认抢锁。独立归还若已移除 Claude 共享引用，后续全机卸载不得继续要求旧引用存在；须依据真实归还事务核验已退休入口与现状，不能洗台账或忽略其他漂移。归还后的台账合法指纹更新须受窄范围保护；注册写失败要回滚，恢复再次失败仍可独立恢复。

人工精确清理只在其专门授权下进行，不当作正式卸载器通过；预览不是已执行回执。备份保留至用户明确允许清理，不因为安装完成就删除。

## 验收标准

验证全机六家 Skill 撤除、公共完整正文直接归还、无导航残留、私文/权限保全、重复来源次数、多轮融合、公共编辑、漂移零写、事务中断/恢复、卸载后全新安装。分别报告只读预览、合成执行与真实卸载；不能用预览通过声称已卸载。

原生 Skill 目录仅在登记对象的正式 committed 安装事务证明创建、且除将撤除的 Skill 外仍为空时纳入精确删除计划；预存目录、未知新增子项及父级 skills 目录保留。锁内复核子项，外置恢复同时恢复目录和权限。

生成公共包装的退休必须有完整 producer before/after 字节链：重现旧逐条包装或现代连续 full-context/根标题省略版式，核对每处创建 offset、完整 after 哈希并回溯到 absent 创建祖先；所有正文 span 已归还才退休剩余包装。用户预存同名标题、未知插入、断链或篡改不可凭形状删除。现机历史空壳的纠正应在正式退出后，按原卸载→fresh→融合证据链单独审精确生成残留，不能在已安装态删除后洗指纹。


## 已共享 CK 通用触发归还

CK 通用正文按事务中原生精确范围还回，保留标准标记与 WorkBuddy 宿主标题，移除公共根后 CK 完整原生入口仍存在。CK 源码与 Skill 不属于 memSharing 删除范围。旧无 CK kind 或替代字段的迁移仍走原协议，不凭标题认领。

更新写回后共享的新来源只替代同 CK 类型、同路径、同主题及公共范围的旧归还关系；引用普通记忆或不同来源的伪造替代必须拒绝。公共 CK 编辑、损坏或源漂移不能丢弃；自动路径阻断，保留正文供明确处置。正式卸载及独立 recover.py 必须以隔离 HOME 完整往返验证，源码结果与真实宿主验收分开。

替代消费前必须拒绝循环依赖，绑定替代前旧事务完整指纹，并从事务备份重放新旧来源的完整 CK 识别、精确删源及 after 指纹；公共范围须追溯到同一创建祖先。缺失或漂移时零写拒绝，不凭替代元数据免除归还。该指纹绑定适用于新 CK 替代记录，未发布的旧格式缺证据时保护性拒绝。
