# 复盘后的最小实施边界

2026-11-03：用户批准复盘，授权先收尾、提交推送，再实施简化方案。

## 收尾裁定

- 保留已经提交的安装、原文保全及失败恢复修复，不改真实安装或备份。
- 尚未提交的单次融合位置映射接线会使第二次正常融合失败，不进入生产。先归档完整补丁与测试，再撤下这批接线；不继续补多事务推断框架。
- 保留复盘和失败事实。撤下退化接线不等于旧卸载已经通过：重复章节的实际归还仍待解决。

## 首个实施切片：Agent 提议，现有执行器精确执行

将当前 Agent 的内容判断显式接入现有整理流程，不新建安装器、记忆服务、日志、锁或恢复引擎。

1. 现有只读预览给出参与者、可操作原文及稳定来源标识。
2. Agent 阅读完整原文，输出一句话摘要并提出分组；语义相近、作用域不同或冲突只能待确认，不凭模型判断自动选中。
3. 提议文件只引用本次已核验的来源组，不接受任意路径、替换正文或新的删除范围；绑定本次读取依据，变更后失效。
4. 用户仍用两块列表和编号选择。未提议的内容不被隐藏或删除。
5. 最终清单和用户确认继续走已有执行器：完整原文先写公共，再精确删除选中来源，复用现有备份、锁和恢复。

它解决“Agent 只能给程序自动分组换个摘要”的局限，不宣称解决了全部卸载或原生新会话问题。原生文件解析只负责定位原文，不升级为通用 Markdown 归还引擎。

## 验收

- 两家相同内容仍按实际覆盖规则默认推荐；不同措辞的内容经 Agent 提议只能进入待选。
- 提议、查看和编号选择不写记忆；源变化、伪造来源、重复使用来源均拒绝。
- 共享后保留完整原文、独有内容和受保护协议；第二次正常融合仍可执行。
- 不增加云模型、hook、服务或另一套事务；项目范围和原有无提议调用保持兼容。
- 测试与源码检查通过才提交；安装物、真实卸载及原生新会话另列，不能冒充已验收。

## 尚未关闭

旧现场重复章节的完整归还、多次共享后的归还与公共内容编辑、真实六家新会话读取。后续应以明确原文关系和可解释差异处理，不以继续扩大章节猜测算法作为默认路线。

## 工作空间边界

用户进一步明确：旧工作区仅收尾、提交推送并合并main；新实现必须在基于最新main的新工作空间进行。本文提供收缩方向，不强制沿用旧解析框架或再造提议文件协议；新空间应先以四步完整用户流程确定最小实现。
