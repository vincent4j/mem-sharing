# 公共用户记忆与融合 PRD

## 记忆归属与常驻内容

保存用户记忆时，适用于所有 Agent 的规则、偏好和长期事实写入公共 memories 对应文件；仅适用于某 Agent 的内容保留于其用户记忆。项目规则和项目经历留在项目。归属不明先澄清，不自动删除或共享专属内容。

MEMORY.md 是精简索引，保留读取、保存归属、自动项目接入及按需操作入口。新增主题加链接；菜单、操作命令和详细流程放 Skill，不复制到公共记忆，不在全新安装中创建重复的“使用约定”手册。正文完整保留，不为压缩索引改写正文。

各家用户入口只留必要公共读取指针；Claude/WorkBuddy 可保留实际使用时补项目入口的短触发。不要重复说明 AI 已知常识、作者身份或环境变量保护细节。

## 读取、分组与选择

完整读取本次实际参与者后，Agent 结合语境与作用域提出方案。读失败/截断为未知，不能当空文件；分母是本次实际参与者，不固定六家。

- 建议合并的相同规则：至少两家参与、所有参与者有同内容且语境/作用域相同。
- 需要你确认是否合并：部分覆盖项及可共享的单家项，默认不选；标来源和单家默认不共享。
- 专属、受保护协议和不明确项不自动迁移。同标题不等于同内容，作用域不同不去重。

所有有资格的部分覆盖和单家候选均须展示，默认不选或不推荐不能等同于不展示；完整 prompt 的编号、来源和候选覆盖不得由外层静默过滤。两块全局连续编号，查看/选择/执行沿用稳定编号；空栏目不展示。Agent 摘要建立在完整阅读上；纯 CLI 只能把忠实截取标为原文摘录，不伪装语义摘要。

`按默认方案` 只选默认项；`不合并2` 排除对应默认项；待选编号在默认方案上追加；支持组合输入。`查看 3` 仅展示完整原文与来源，零写、不选择。无效或含糊选择只澄清必要范围。

## 选择即执行

用户明确选择即授权执行该方案，不要求第二次“确认执行”。方案须让用户理解迁入公共、核验入口后删对应重复片段、未选和专属保留及备份安排；提供完整原文查看入口。

执行时仍生成可审计完整修改清单，含参与者、编号、原文、作用域、精确字节范围、公共目标、源删除片段、入口和恢复位置。内部批准记录绑定真实用户选择及实际计划，不能虚构用户见过另一份清单。查看不是批准。执行前出现实质变化，停止并说明差异，不能沿用旧选择静默扩大操作。

## 写入、去重与清理

先写公共全文，核验公共与读取入口，再删精确来源片段。仅正确分组、作用域及原文字节满足去重条件才存一份；保留每处来源与次数，支持后续逐处归还。同名章节、重复出现及不同语境单独处理。

已有有效公共指针时复用，不另加第二个 `memory-index` 指针。对历史重复的产品受管指针，确认所有权与目标后只保留一个有效入口，兼顾台账、恢复及重复安装；不得按任意相似文本粗删。

迁移后“用户规则”章节确实为空，移除空标题和多余空行；仍有未选或专属正文就保留。代码块内示例、其他作用域同名标题不误删。空壳清理与正文迁移属于同一可恢复修改计划。

## 验收标准

覆盖全覆盖/部分/单家/未知/同标题不同语境、查看零写、选择后直接执行、第二次增量共享、公共新增编辑、私文漂移拒绝、同作用域去重与来源次数、指针复用、空章节清理、崩溃后恢复。失败不得丢失正文、伪报完成或放宽漂移保护。

## 参与与边界判定

缺失或空来源记为无内容，读取失败/截断记为未知；未知不能当空值或据此推定全覆盖。N≥2 且全部参与者同语境同内容才默认共享；部分覆盖与 N=1 保留待选。近似、冲突或格式差异不盲并，不丢任一原文变体。只改变本次选定范围，不能顺带整理其他项目、用户私文或项目经历。

界面类别统一为“用户记忆、项目记忆、项目经历”，操作动词用“共享”；技术文件名可以保留。不用测试数、代理数量或配置声明代替用户可用性；正常第二次共享、公共后续编辑和退出是验收的一部分。

公共正文按来源自然顺序写入；相邻同语境条目复用工具生成的包装标题，不逐条重复。仅处理合成包装，不改原文标题、代码块或不同作用域；增量保留已有公共前缀，并核对每处迁移偏移和来源次数。

标题不同但语义等价时，允许 Agent 在提案中显式绑定每处源路径、范围、原文哈希、Agent 实际读取的源与公共整文件基线及真实源 context，与已证明的既有公共 span/context，并说明等价理由。工具只校验精确绑定，不代替语义判断；未声明、错误或部分组声明拒绝或沿默认保护，不形成永久别名。复用不写公共正文，原迁移 record 保留真实源语境和次数；旧版正式归还、卸载与外置恢复必须可消费。

Agent 实际阅读完整上下文后，可提交本次 `equivalent_sources`：逐来源整文件基线、路径、范围、真实 context、原文哈希和等价理由，canonical 公共语境来自真实来源。同字节且已明确语义等价的规则只显示一个编号，查看/排除/追加/执行覆盖该编号全部来源，保留原迁移记录 context 与次数，不形成永久别名。部分声明、重叠、错基线或漂移拒绝；无声明沿严格分组。


## Context Keeper 通用触发正文例外

用户选择后，当前已核验的完整通用触发正文可共享一份；标准与 WorkBuddy 标记、宿主标题和其他字节留原生。候选保留真实源 context 与全部来源次数，内部协议归组不改写源语境。公共正文必须被既有原生→公共 MEMORY.md→必读 user-rules.md 链覆盖，按需索引不足以执行。普通、未知或部分 CK 块继续受保护。

公共与源全文基线绑定完整选择，查看、拒绝零写。上游安装器正常写回后再整理，复用已有 producer 证明的同字节公共范围；同源替代记录必须校验 CK 类型、路径、主题、正文与公共范围，不能消费普通迁移。历史次数保留，退出只恢复当前入口一次。公共 CK 正文修改时保护性阻断，不能悄悄新增第二份。

替代消费前必须拒绝循环依赖，绑定替代前旧事务完整指纹，并从事务备份重放新旧来源的完整 CK 识别、精确删源及 after 指纹；公共范围须追溯到同一创建祖先。缺失或漂移时零写拒绝，不凭替代元数据免除归还。该指纹绑定适用于新 CK 替代记录，未发布的旧格式缺证据时保护性拒绝。

Claude 已复用的原生引用在 CK 更新后，仅当删除完整已审正文恰好还原台账指纹，且存在该原生壳的未归还 CK 来源证明时可继续整理；引用与兜底协议保持原字节。混入其他编辑仍按漂移阻断，不放宽一般整文件归属门禁。
