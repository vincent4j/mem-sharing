# 整机卸载与直接归还合同

## 范围与来源

正式入口为 `python3 -B scripts/agm.py uninstall-machine --backup-dir ABS`；默认只读预览，精确批准后追加 `--approval-file ABS`。独立可信工具仍须验证固定 Git pin、已安装 C 的身份和现有台账，不可绕过 active-code、所有权、同版异源、旧升级前身或漂移门禁。当前源码修改不是已发行产品；真实机器已卸载时不得调用不存在的 installed C，也不自动重装。

新计划显式携带 `memory_return=native-direct-v1`。缺少此字段的旧恢复计划只按旧格式恢复，不自动改成新归还语义；未知新值拒绝。

## 公共用户记忆直接归还

公共源 MEMORY 及其必要用户主题必须完整核对；现存历史原文不因为名为 legacy 就丢弃。已知产品模板、生成治理段、读取预算和索引控制、产品菜单、安装卸载说明及产品路径依赖全部退休。尤其已知生成的“公共记忆”标题与五条治理句是一个完整产品单元；单句不含产品名也不因此变成用户偏好。识别依赖精确模板和来源范围，不按 Context Keeper、AGENTS 或其它宽泛词删除用户原创。未知或定制相似材料在预览明确待审并阻断执行。

其余公共用户记忆原文直接合并到六家已有原生用户文件。用户主题沿规范内部路径展开，不能留下指向待删除目录的链接；缺失、逃逸、符号链接、循环或不可内联资料拒绝，不假装完整。未链接的用户历史正文同样纳入来源清单。只对完全相同的完整条目去重，不摘要、不选取少数偏好。用户自己的同名标题、独有正文、Context Keeper 协议、字节顺序、BOM、CRLF 与文件权限保全。合法 Context Keeper span 先验证边界并作为不透明字节片段贯穿分类、历史说明清理、主题展开、合并及残余检查，不使用可碰撞的文本占位词；嵌套、缺失或反向 marker 零写拒绝。独立来源组合出的多个完整 span 作为整体保全和精确去重，不在 span 内拆段落。保护只禁止改写，不免除依赖安全：明确活动 import/link/受管 symlink 指向待删根仍拒绝；不能证明惰性的裸路径也保持待审阻断，不凭语境猜测为历史示例。

目标必须已经存在且为普通文件，不擅自创建。按登记证明和原指纹拆除自有块/import，不改变所有权或扩大删除权。Claude reused import 保持 whole-file 指纹校验；合法 BOM 不妨碍识别，原 BOM 与非自有换行保留。旧 DSH 非受管引用仅在明确转换批准和精确原文证明下去除，不能把任意用户路径洗成产品所有权。

禁止新建 memsharing-return、索引或归还读取指针。已有旧 return 必须严格证明旧 producer 的完整文件集合和原始内容，未知/漂移同名目录拒绝；归还校验通过后才按精确清单清除，不能先删恢复来源。

## 预览、备份与执行

预览绑定完整公共源、台账、既有入口及受管对象、before/after bytes 与 mode、原生 inode/dev、精确删除树及宿主义务。批准为 `{plan: <原精确摘要>, reference: <真实确认>, confirmed_at: <真实UTC>}`；批准后重新生成计划，任何变化拒绝，不换哈希自动批准。

真正执行唯一可新增的文件在外置恢复备份根内：完整 before、必要 manifest 状态、标准库独立 recover.py，以及确实必要的独立解释器。不得新增日志、报告、receipt、事务、锁、临时文件或所谓归还目录。新计划分支原地 r+b/truncate/fsync 写已有原生文件，保持权限和 inode。现有 writer/活动标记仍拒绝；每次写前完整 scene 和 inode/hash 复核，中途失败保留恢复材料且不自动覆盖潜在外部新改。无新锁的模式不提供跨进程原子事务保证，也不宣传拥有“锁内”互斥。

先验证备份可独立读取、恢复代码语法和所有 before 字节，再写六家；六家全文与不透明正文读回全部通过才删除产品。逐精确文件 unlink、空目录 rmdir，不递归吞掉未知后代；项目 AGENTS 主体和独立 Context Keeper 保留。已证明归属的历史备份容器沿既有严格 producer 校验，活动、未知与伪造材料继续阻断。

## 宿主、清理和验收

机器资产、Paseo host 与整体状态分开报告。准确插件 ID 只能经官方 remove 一次，随后同 serverId/daemon PID 的完整列表确认缺席；disabled 不算移除，其他插件必须不变。官方配置原子临时文件是用户明确批准的唯一宿主例外，完成必须无残留；不私改配置、不伪造 producer/receipt，不省略已知宿主义务。仍沿现有 host binding 和检查门禁，不因机器完成解锁 Context Keeper 卸载。

安装根、库存、导出、暂存、旧 return、产品专属引用及已证明非活动恢复容器均须在精确清单。开发仓库/worktree、既往 QA/审计备份、当前 daemon/会话数据库未有精确删除授权就保留，并明确不等于全机历史零相关文件。

root 独立验收六家完整正文、opaque/Context Keeper、权限、删除根、宿主和临时文件残留后，按本次已批准清单删除本次所有恢复备份；无需用户重复手动验收。失败则保留备份并报告。`recover-uninstall --manifest ABS` 始终先预览当前恢复现场并要求独立精确批准，不覆盖第三种用户现场。恢复运行时与标准库 runner 不能依赖已删 C。

## 验证边界

专项六家临时 HOME 测试覆盖完整主题归还、生成治理整段退休、用户同名正文和 Context Keeper 保全、缺失/路径/符号链接/循环/所有权与漂移拒绝、无新增生产路径、备份恢复及幂等变换。旧历史 producer/宿主消费测试仍保留门禁。源测试通过不代表已发行，也不代表真实六文件已应用本轮纠正或原生新会话已验收；现机纠正另按核验后的正式接口与精确计划执行。
